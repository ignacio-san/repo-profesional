Sistema de Tienda — TiendaFrontCL

TiendaFrontCL · Frontend + Integración Backend Autor: Ignacio Sánchez Versión: v1.0.0

Plataforma frontend mobile-first para un e‑commerce real conectada al backend de la tienda.

Resumen

La solución es un frontend Next.js (App Router) optimizado para móvil que consume APIs del backend para catálogo, carrito, órdenes y pagos. Ofrece navegación rápida, carrito persistente con x-session-id, merge al autenticar y checkout seguro con idempotency keys. Soporta storefront y paneles admin protegidos por roles.

Alcance del proyecto: storefront público responsivo, integración de carrito persistente mediante identificadores de sesión anónimos (x-session-id), lógica de unificación (*merge*) de canastas al autenticarse y un módulo administrativo blindado mediante políticas de acceso basadas en roles (RBAC).

Impacto del proyecto

  • - Mejor experiencia móvil con menor tiempo de carga y menos fricción al comprar.
  • - Carrito persistente y merge fiable entre sesiones anónimas y autenticadas.
  • - Checkout seguro con reintentos controlados y trazabilidad de pagos.
  • - Historial y auditoría de órdenes para atención al cliente y reconciliación.
  • - Herramientas admin para mantener catálogo, stock y promociones en tiempo real.

Objetivos del proyecto

  • - Proveer una UI mobile-first rápida y accesible para catálogo y checkout.
  • - Minimizar JS cliente usando Server Components y aislar islas interactivas.
  • - Implementar cliente API centralizado con manejo uniforme de errores y tokens.
  • - Garantizar flujo de carrito robusto (sessionId + merge + token backend).
  • - Permitir operaciones admin seguras y controladas por roles.

Módulos principales

  • 🔸Catálogo: listados paginados, filtros, búsqueda y páginas de detalle.
  • 🔸Carrito: persistencia anónima (x-session-id), CRUD de items, merge al login.
  • 🔸Checkout y Pagos: creación de órdenes, /pagos/iniciar, idempotency keys.
  • 🔸Autenticación: Firebase → register-or-login → JWT backend.
  • 🔸Admin: gestión de productos, inventario y órdenes con control de roles.
  • 🔸Cliente API: apiFetch central con ApiError, encabezados estándar y manejo de payloads.
